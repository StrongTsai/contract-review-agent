# 合同审核数字员工 · 需求文档

> 版本 v1.1 · 2026-09-12

## 1. 项目背景

- **目标**:为求职面试准备一个可展示、可深挖的端到端智能体(agent)项目。
- **动因**:已系统读完 LangGraph / agent-service-toolkit 的常用模式(interrupt、记忆、supervisor/handoff),纯读框架边际收益见底,需从「读」转向「造」。
- **定位**:一个「合同审核数字员工」——输入合同文本,高危风险经人工确认后,输出结构化审核报告。

### 决策链(为什么是合同审核,而非其他方向)

客服 agent → 嫌技术含量低 → 多模态方向(工业质检 / 文档理解 / 场景预警)→ 受限于只有 DeepSeek(纯文本、无视觉能力)→ 定架构「OCR 当眼睛 + DeepSeek 当大脑」→ 文档/合同审核最可行(本地 OCR 零成本、不 low、契合背景)。

## 2. 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| FR-1 | 信息抽取 | 从合同原文抽取标的、签约方、金额、期限、关键条款 |
| FR-2 | 风险审核 | 识别风险条款,给出风险类型、等级、理由、修改建议 |
| FR-3 | 报告生成 | 将抽取结果 + 审核结果拼成人类可读的《合同审核报告》 |
| FR-4 | 高危人工确认 | 审核出「高」等级风险时,先暂停、把风险展示给人工;人工批准才生成报告,驳回则不生成 |

## 3. 非功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| NFR-1 | 结构化输出 | 抽取/审核结果必须符合固定 schema(Pydantic),可程序化消费 |
| NFR-2 | 防幻觉 | 金额/期限缺失时填 None 而非编造;无风险时不凑数 |
| NFR-3 | 可观测性 | 每次运行可追踪完整链路(token、耗时、每个节点的输入输出) |
| NFR-4 | 密钥安全 | 真实密钥只存 `.env`,不进 `.env.example`、不进版本库 |
| NFR-5 | 状态可恢复 | 图可中断、可续跑,人工决策存进状态、可追溯(checkpointer) |

## 4. 技术约束

- 仅有 DeepSeek API key,模型无视觉能力。
- 多模态通过「本地 OCR 提取文字 + LLM 推理」的异构架构解决(后续扩展,当前为纯文本版)。

## 5. 验收标准

- [x] 运行 `python main.py samples/contract.txt` 能端到端输出审核报告。
- [x] 报告包含:标的、签约方、金额、期限、整体风险等级、审核结论、逐条风险(等级/理由/建议)。
- [x] LangSmith 能追踪到完整运行链路。
- [x] 高危风险先暂停、打印风险点、等人工输入 `y/n`;`y` 出报告,`n` 不生成报告。

## 6. 后续规划(未实现)

- **RAG 知识库 + agent 化**:接入法条/判例/模板检索,审核节点可自主查证,从固定流水线进化成自主 agent(检索即工具)。
- **OCR 接入**:扫描件/PDF → 本地 OCR → 文本 → 现有流程(真正的「多模态数字员工」)。
- **supervisor 多智能体**:抽取/审核拆成多专家 agent 并行。
